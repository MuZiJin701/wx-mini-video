# macOS 版本需求澄清

状态：需求讨论中，尚未确认完整方案或开始实现。本文只记录已确认需求、代码事实和待决策项，不表示已有 macOS 可用版本。

## 已确认需求

2026-10-20 第一轮确认：

- 在 Mac 本机运行，嗅探同一台 Mac 上微信小程序的媒体。
- 保留图片、直链视频、直链音频及 m3u8 媒体下载的完整核心流程。
- 首版面向普通用户公开发布。
- 同时支持 Apple Silicon 和 Intel Mac。

第二轮确认：

- 沿用终端 TUI，提供双击后打开终端的入口及中文说明；用户无需安装 Go 或输入启动命令。
- 正式公开发布必须完成开发者签名与 Apple 公证；尚未执行账号、付费、签名或上传操作。
- 首次使用通过 macOS 系统提示授权设置代理、安装并信任本机独立根证书，日常 TUI 以普通用户运行。
- 退出自动恢复原代理；根证书信任持续保留，并提供卸载说明。

第三轮确认：

- 首版系统目标为 macOS 13 及以上；微信优先支持发布验收时的官方最新稳定版，公开说明实际通过验收的版本组合。目标范围不表示所有组合均已验证。
- 提供一个同时支持 Apple Silicon 和 Intel 的 DMG，用户拖入“应用程序”后双击启动 TUI。
- 发布包不内置 ffmpeg；首次下载 m3u8 时自动获取与处理器匹配的固定版本并校验，保留手动指定路径。
- 发现已有代理或 VPN 配置冲突时提示处理；运行中切换 Wi-Fi/有线网络时暂停嗅探并提示重新启动代理，退出恢复本程序改动过的原设置。
- 两种架构分别完成真实微信、图片、直链视频、直链音频、m3u8、首次授权、双击启动及代理恢复验收后，才能正式发布。用户表示可安排相关资源；具体环境和签名条件在执行前核实。

## 已知约束

- 现有领域规则继续适用：按请求来源 AppID 严格匹配目标 AppID；缺少可信来源信息时不能放宽过滤。见 [ADR 0003](adr/0003-target-appid-filtering.md)。
- 系统代理、证书信任库和部分进程操作目前只有 Windows 实现，不能仅增加构建目标就宣称支持 macOS。
- TUI、目标选择、媒体识别及主要下载流程可以作为复用基础；现有受管 ffmpeg 自动获取仅面向 Windows，macOS 对应资源、校验和执行权限仍需适配。
- Mac 微信是否使用系统 HTTPS 代理、接受本机根证书并提供过滤所需来源信息，须用真实微信验证；构建成功不能代替此项验收。
- 已进行一次 `darwin/arm64`、`CGO_ENABLED=0` 编译探查，因缺少系统与证书平台函数失败，未生成 macOS 程序；这只证明当前适配缺失。
- 签名与公证遵循 [Apple Developer ID 站外分发流程](https://developer.apple.com/developer-id/)，不能代替真实微信功能验收。

## 待澄清

- 默认文件位置：用户要求“和 Windows 类似”，尚未确认是否要求物理位置同样在程序旁。已明确向用户解释推荐方案：保持自动创建目录、按 `o` 打开、升级保留文件的操作体验，macOS 媒体默认放在用户“下载/wx-mini-video”；配置、证书和受管工具位置由程序处理，无需用户管理。此建议尚未视为已接受。
- 全部需求澄清后，汇总方案并由用户确认达成共同理解，再开始实现。
