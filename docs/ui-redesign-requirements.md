# 微信小程序媒体下载器 UI 重设计需求（v0.2.0）

状态：需求已确认（2026-10-25），待实现。
关联：[GLOSSARY](../GLOSSARY.md) · [ADR 0011](adr/0011-single-main-surface-ui.md) · [ADR 0012](adr/0012-per-appid-download-layout.md)
观感参考：`wechat-channels-downloader`（外部项目，仅借鉴观感与交互范式；布局按本项目的信息量与流程自行设计）。

## 1. 背景

v0.1.9 的 TUI 是三屏结构（AppID 输入 / 小程序发现 / 媒体列表）+ 高密度纯文本表格 + 常驻详情与日志：没有品牌区、没有浅深色、没有鼠标点击，分类页签与表格列宽按 rune 而非显示宽度计算，窄终端易错位。候选可达上百条，但「小程序名称」只用于顶栏、发现列表与文件名，既不参与归属判断，也不持久化。

参考项目提供了一套更清晰的品牌化终端界面：品牌区、浅/深色跟随系统、大留白、可点击控件、单一结果反馈。本版目标是把这套观感与交互范式引入本项目，同时保留嗅探与下载能力，删除名称功能，并把下载产物按小程序与资源类型分类存放。

## 2. 范围

### 2.1 保留

- 单二进制 Go TUI；Echo 代理适配；Windows/macOS 系统代理与证书；随包与受管 ffmpeg。
- 目标 AppID 严格归属与来源未确认媒体（`?` 标记）机制（ADR 0008）。
- 手动输入 AppID 与小程序发现两条入口。
- 键盘操作、`--debug` 诊断日志、单目标嗅探、清空列表（`c`）、分类查看。
- `capture.showUnattributed` 配置语义不变。

### 2.2 删除

- **小程序名称**功能：输入、发现列表展示、确认步骤、候选字段、配置项、文件名前缀、术语表与用户文档提及、相关测试断言（详见 §6）。
- 三屏跳转式交互由「单主界面 + 目标选择覆盖层」替代，不保留旧的独立输入页/发现页。

### 2.3 非目标

- 不迁移 Textual/Python，不引入 Web UI。
- 不做批量下载队列；发现列表不跨启动持久化。
- 不改动嗅探与归属规则、不改动 ffmpeg/证书/代理机制。
- 不做系统通知、播放器、下载完成后自动打开目录。

## 3. 界面信息架构

### 3.1 主界面（唯一常驻界面）

从上到下四段：

1. **品牌区**：左侧品牌图标（真图，探测失败时为块字符降级）+ 三行文字——kicker `WX-MINI-VIDEO / 媒体嗅探`、标题「微信小程序媒体下载」、副标题「保存小程序里值得留下的图片与音视频」；右侧「外观」分段控件。
2. **渐变分隔线**：1 行真彩渐变，主题切换时重建。
3. **主区**：
   - **未选目标**：目标选择卡——AppID 输入框、「开始嗅探 · Enter」主按钮、「自动发现 · Ctrl+D」次按钮、引导文案与内联错误提示。
   - **已选目标**：目标条（`目标 <AppID> · 代理 <addr> · ffmpeg <状态>` + 右侧「切换 · s」）+ 分类页签 + 候选表格 + 底部状态/进度行。
4. **底部栏**：左侧 GitHub 链接（`GitHub · MuZiJin701/wx-mini-video ↗`），右侧「退出 · Ctrl+Q」按钮。

覆盖层与抽屉（叠加在主界面上，不切换整页）：目标选择覆盖层、详情抽屉、日志浮层、退出确认、旧证书确认、网络暂停提示、错误提示。

### 3.4 各界面细节

- **目标选择卡**：输入框只接受 AppID；Enter 直接确认并启动嗅探；AppID 为空时内联报错「请先输入小程序 AppID」并聚焦输入框；格式提示见 §7.5。
- **目标选择覆盖层**：标题「选择小程序」；行格式 `● <AppID>   最近出现 HH:MM:SS`（当前目标用 `●`，其他用空格）；按最近出现时间倒序；空态显示「还没有发现小程序。请在 PC 微信打开目标小程序，或按 Ctrl+D 手动输入 AppID。」；Enter/点击即确认目标并关闭覆盖层（不再有任何名称补填步骤）；Esc/Ctrl+D 取消并回到来源界面。
- **目标条**：AppID 超长时中间省略；代理地址与 ffmpeg 状态用 muted 色；右侧「切换 · s」可点击。
- **分类页签**：`1 全部(N)`…`5 音频(N)`，Tab/Shift+Tab 循环、`1`–`5` 直达、可点击；计数每帧全量统计（候选上限小，无需缓存）。
- **表格列**：时间（`HH:MM:SS`）/ 类型 / 归属（`✓`、`?`）/ 大小（人类可读）/ 来源（响应、H5、JSON）/ 标题；host、文件名、完整 URL、请求头、本地路径进详情抽屉。列宽按显示宽度计算；窄终端按「来源 → 大小 → 归属」优先级隐藏列，标题保持弹性宽度。选中行整行反色/高亮。
- **已下载候选**：行尾显示「已下载」；仅本进程内按候选 ID 标记，重启不保留；详情抽屉显示本地路径；重复下载生成新文件，不覆盖旧文件。
- **状态/进度行**：空闲时显示代理与嗅探提示；下载中显示 `下载中 42% [██████░░░░░░] 1.2/3.0 MB`（未知总大小时用 spinner）；完成时显示「已保存 → <相对路径>」；失败时显示「下载失败：<原因>（Enter 重试 / l 查看日志）」。
- **详情抽屉**：`i` 开关；字段至少包含标题、类型、归属、来源 AppID、判定依据、URL、来源 URL、请求头、本地缓存、本地路径、大小；超出可视高度时在抽屉内滚动。
- **日志浮层**：`l` 开关；沿用现有日志内容（时间 + 消息）与滚动键；顶部显示日志文件路径。
- **退出确认**：仅下载中触发；文案「正在下载，退出会中断当前下载（已完成文件保留）。Enter 确认退出 / Esc 取消」；非下载状态按 `q`/`Ctrl+Q` 直接进入退出流程。
- **旧证书确认 / 网络暂停 / 退出失败**：改为覆盖层或专用错误页，按钮可点击且保留键盘等价键。

### 4.2 布局度量

- 品牌区：左右内边距 4 列、上下 1 行；标题上下各 1 行间距。
- 主内容：左右外边距 4 列 + 内边距 2 列（正文左边缘比品牌文字右移 2 列）；上下内边距 1 行。
- 渐变色带：左右缩进 4 列，高 1 行。
- 底栏：左右 4 列、底部 1 行。
- 控件高度：输入框 3 行、按钮 3 行（1 行文字 + 上下边框）、分段控件 1–3 行；按钮最小宽度 16 列、按钮间距 1 列。
- 响应式断点：宽 `< 76` 为紧凑（去外边距、隐藏副标题与外观标签、按钮纵向堆叠）；宽 `< 52` 为窄屏（品牌区纵向排列、外观控件独占一行）；高 `< 32` 为矮屏（品牌区压缩、隐藏 kicker/副标题、主区顶对齐）。
- 无强制最小尺寸；在 44×20 下仍应保证底栏可见、候选可选中、按钮可操作（由主区滚动兜底）。

### 4.3 品牌区与 logo

- 品牌文案固定为：kicker `WX-MINI-VIDEO / 媒体嗅探`、标题「微信小程序媒体下载」、副标题「保存小程序里值得留下的图片与音视频」。
- **真图 logo（首选）**：启动、进入 TUI 之前探测终端图形能力（kitty 查询 + `CSI 16t` 像素格 + DA1 判断 Sixel/kitty），探测不到直接降级，绝不按操作系统名猜测。图片资产为新增的 512×512 PNG（品牌图标），通过 `go:embed` 打包，不进入分发包目录。
- **绘制要求**：图片只在品牌区固定位置显示；主题切换、窗口缩放、覆盖层遮挡、退出时需正确重绘/清理；不得破坏表格渲染与鼠标命中计算；不得让 `NO_COLOR`、tmux/screen、Apple Terminal、矮窗口等场景出现残影。
- **降级**：探测失败或运行中无法维持时，回退到「块字符像素图标」（真彩半块字符绘制的 3 行图标，纯文本）；再失败则纯文字品牌区。
- **原型门槛（实现前置）**：先做原型验证——Windows Terminal 下图片稳定显示、连续导航无闪烁、切主题/改窗口后重绘、退出清理干净、表格不被破坏；通过才正式接入，失败则只交付块字符方案并记录原因。
- 图片编码优先自写最小 Sixel/kitty 编码（避免新增依赖）；确需新增 Go 依赖时须更新 `THIRD-PARTY-NOTICES.md` 并复核许可。

### 4.4 宽度与中文字符

- 所有列宽、截断、边框、居中、鼠标命中计算必须使用显示宽度（`lipgloss.Width` 或等价实现），禁止按 rune 数补齐；这是 v0.1.9 表格错位的根因。
- 截断以 `…` 结尾，不切断组合字符；标题列优先保留左侧内容。

## 5. 交互规格

### 5.1 键位

保留现有单键操作，新增鼠标点击，并提供参考项目风格的 Ctrl 别名：

| 按键 | 作用 |
| --- | --- |
| `↑/↓`、`k/j` | 候选/列表行移动 |
| `d`、`Enter` | 下载选中候选（未选目标时 Enter 为确认 AppID） |
| `Tab`、`Shift+Tab` | 分类页签循环 / 焦点切换（覆盖层与控件内） |
| `1/2/3/4/5` | 全部 / 图片 / 视频 / m3u8 / 音频 |
| `s` | 打开目标选择覆盖层（当前目标保留，Esc 取消） |
| `Ctrl+D` | 打开目标选择覆盖层（手动输入与自动发现同层） |
| `c` | 清空候选列表（不删本地文件；下载中不可用） |
| `i` | 详情抽屉开关 |
| `l` | 日志浮层开关 |
| `PgUp/PgDn/Home/End` | 日志与列表滚动 |
| `o`、`Ctrl+O` | 打开当前目标目录（未选目标或目录不存在时打开下载根目录） |
| `r`、`Ctrl+R` | 代理失败时重试启动；否则刷新候选 |
| `q`、`Ctrl+Q` | 退出（下载中需二次确认） |
| `Esc` | 关闭覆盖层/抽屉/浮层；输入页取消焦点 |
| `y/n` | 旧证书确认覆盖层的清理/保留 |

### 5.2 鼠标

- 启用单元格级鼠标事件；可点击区域：外观分段控件、目标选择卡按钮、目标条「切换」、分类页签、表格行（单击选中、双击下载）、状态行重试入口、底栏链接与退出按钮、覆盖层条目与按钮、详情/日志面板滚动。
- hover 提供边框/底色变化；点击与键盘操作等价，所有操作保留键盘路径。
- 命中区域在布局计算阶段确定，与渲染共用同一套坐标，避免缩放后错位。

### 5.3 反馈与并发

- 同一时刻只允许一个下载；下载中 `d`/`Enter` 不重复触发，目标切换、清空列表保持现有禁用语义（下载中不可切换）。
- 主题切换不打断下载、不清空输入与结果。
- 错误优先显示在状态行；需要用户决策的错误（旧证书、退出失败、退出确认）使用覆盖层。

### 5.4 外观模式与持久化

- 外观分段控件：`跟随系统 | 浅色 | 深色`，`←/→` 或点击切换，立即生效；焦点态有边框提示。
- 偏好持久化到 `downloads/ui.json`：`{"appearance":"system|light|dark"}`；原子写入（临时文件 + rename），读取失败或值非法时回退 `system` 并给出一次状态行提示；不写回 `wx-mini-video.yaml`。
- 「跟随系统」在 Windows 读取注册表 `AppsUseLightTheme`，在 macOS 读取 `defaults read -g AppleInterfaceStyle`；启动时与运行中每 2 秒轮询（仅在跟随系统模式）；读取失败按深色处理。

## 6. 小程序名称删除

### 6.1 影响面

- 领域模型：`Target.Name`、`Candidate.AppName` 字段删除；发现列表只登记 AppID。
- 配置：移除 `target.name` 注册项与模板项；旧 yaml 中的该键被忽略（不报错、不迁移）。
- 交互：输入页不再有名称输入框；发现列表不再显示「名称未识别」；选择已发现 AppID 后立即确认，不再有「补填名称」二次 Enter。
- 命名：文件名的名称前缀改为新的命名规则（§7.3）。
- 文案：README/README.en、GLOSSARY、知识文档、界面引导中所有名称相关表述删除或改写；`docs/archive/` 历史归档保持原样。
- 测试：删除名称相关断言；新增「名称不再出现」与「选中即确认」回归用例。

### 6.2 行为变化

- 目标标识统一为 AppID；界面所有展示（目标条、发现列表、详情、日志）只用 AppID。
- 旧配置带 `target.name` 时忽略该键；运行时不再有名称概念。
- `docs/archive/` 与 CHANGELOG 中关于名称的历史记录保留（历史事实），不作为现行功能。

## 7. 下载目录与文件命名

### 7.1 目录树

```text
downloads/
├── <目标 AppID>/                 # 目标目录
│   ├── 图片/
│   ├── 视频/
│   ├── 音频/
│   ├── m3u8/                     # 合并产物 + 播放列表缓存 + .segments 临时目录
│   └── 其他/                     # 未识别二进制等
├── wx-mini-video.log
├── wx-mini-video-debug.log
├── history.jsonl
├── ui.json
├── WxMiniVideoRoot.cer
├── ffmpeg.exe（macOS: ffmpeg） + 校验标记
└── .ffmpeg/                      # ffmpeg 失败日志
```

### 7.2 归档规则

- **目标目录**：用候选资源自身的 AppID 决定；来源未确认候选按「下载时的当前目标 AppID」归档（历史记录同时保存请求来源 AppID，供追溯）。这样切换目标后下载旧的未确认候选，会落入新目标目录——这是已接受的取舍。
- **资源分类**：图片 / 视频 / 音频 / m3u8 / 其他，与界面分类一致。m3u8 判定沿用下载器现有逻辑（kind 或 URL 扩展名），确保合并产物、播放列表缓存与分片目录分到同一处。
- **m3u8**：合并后的 `.mp4`、播放列表缓存（`<候选ID>.m3u8`）、分片临时目录 `.segments/<候选ID>/<播放列表哈希>/` 全部位于 `<目标目录>/m3u8/`；下载成功后的分片清理沿用现有语义（默认删除，保留开关不变）。
- **直链媒体**：直接保存为 `<目标目录>/<类型>/<文件名>`；`.part` 续传文件与 `.part.json` 跟随输出文件放在同一目录，旧版根目录 `.part` 不再复用。
- **运行时文件**留在 `downloads/` 根：运行日志、debug 日志、`history.jsonl`、`ui.json`、根证书导出、受管 ffmpeg 与校验标记、`.ffmpeg/` 失败日志。目标切换、清空列表都不删除这些文件。
- 旧版平铺在 `downloads/` 根的媒体文件不迁移、不删除、不被新逻辑复用（重复下载会生成新文件）。

### 7.3 文件命名

- 规则：`<类型前缀>_<YYYYMMDD-HHMMSS>_<候选ID前8位>.<扩展名>`，时间取下载开始时的本地时间。示例：`图片_20261025-130000_1a2b3c4d.jpg`、`视频_20261025-130512_9f8e7d6c.mp4`、`m3u8_20261025-130733_5a4b3c2d.mp4`。
- 类型前缀：`图片`、`视频`、`音频`、`m3u8`、`其他`。
- 候选 ID 为空时用 `copy` 占位；同名冲突追加 `_2`、`_3`；m3u8 合并产物扩展名固定 `.mp4`。
- 文件名中的 AppID、类型、时间、短 ID 在写入前统一做文件系统安全清洗（复用现有 `safeOutputName` 规则）。
- 不使用 URL 原始文件名，避免随机哈希与超长名称；原始 URL 记录在详情与下载记录中。

### 7.4 目标 AppID 的目录名安全

- AppID 成为目录名前必须清洗：替换控制字符与 `<>:"/\|?*`；拒绝 `.` 与 `..`；去掉首尾空格与结尾点；Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`）加前缀；空值回退 `_unknown`。
- 拼接后校验路径仍在下载根目录内（拒绝路径穿越）。
- 保持 AppID 原始大小写；Windows/macOS 文件系统大小写不敏感，同名不同大小写时复用已有目录（并记录一次提示），避免跨目标混放。
- 手动输入宽松校验：只拒绝空值与路径不安全字符，提示「通常以 wx 开头」；不做严格格式校验，避免误拒非常规 AppID。

### 7.5 下载记录

- `history.jsonl` 继续位于下载根目录，每条记录新增 `app_id`（目标目录归属）、`kind`、`attribution`、`source_app_id` 字段；保留 `path`、`source_domain`、`size`、`completed_at`。
- 记录只在下载成功后追加；失败与中断不写记录。

### 7.6 打开目录

- `o`/`Ctrl+O`：目标已选且 `<下载根>/<目标目录>` 存在时打开该目录；否则打开下载根目录。日志与状态行给出实际打开的路径。

### 7.7 路径长度与平台约束

- m3u8 分片路径会叠加候选 ID 与播放列表哈希，深目录下可能接近 Windows 260 字符限制；实现时评估缩短（如分片目录使用候选 ID 前 8 位）并做路径长度防护，文档中说明便携应用目录不宜过深。
- macOS 路径组件上限 255 字节；AppID 与类型目录名远低于上限。

## 8. 配置与持久化

- `wx-mini-video.yaml`：保留 `download.dir`、`download.ffmpeg`、`capture.showUnattributed`、`target.appID` 等现有项；删除 `target.name`。
- `downloads/ui.json`：外观模式偏好；原子写入；损坏或非法值回退默认；不写回 yaml。

## 11. 风险与待验证

- **Sixel/kitty 在 Bubble Tea 下的稳定性**：渲染器逐行 diff 重绘，没有后置渲染钩子；需原型确认无闪烁、无残影、无表格破坏。失败则回退块字符方案。
- **终端能力差异**：传统 conhost、Apple Terminal、SSH/tmux 下只能文字版；真彩色不可用时降级 256 色，观感会下降。
- **中英混排宽度**：所有布局统一按显示宽度计算，需专门单测覆盖。
- **路径长度与大小写**：m3u8 分片深路径、AppID 大小写、Windows 保留名需按 §7.4/§7.7 处理。
- **测试与文案大改**：现有 View 字符串断言几乎全部需要重写；按 §9.1 的纯函数测试优先，减少对完整界面文案的耦合。
- **未确认候选归档取舍**：切换目标后下载旧的未确认候选会落入新目标目录，用户可能误以为归属正确；详情与下载记录中保留来源 AppID 供核对。
