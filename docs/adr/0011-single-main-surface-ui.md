# TUI 改为单主界面品牌化布局，并删除小程序名称

状态：已实施（2026-10-25）。本日后续修订以[已确认需求](../tui-alignment-requirements.md)为准；统一目标选择区、视觉对齐与交互已按该需求实施，实现差异见文末“实施记录”。

## 背景

v0.1.9 的 TUI 是三屏（AppID 输入 / 小程序发现 / 媒体列表）+ 高密度纯文本表格 + 常驻详情与日志。它信息密度高，但缺少品牌区、浅深色、鼠标点击与留白层次；表格列宽按 rune 补齐，中英混排时错位；分类页签与快捷键提示混在头部。候选可达上百条，界面没有一个稳定、可辨认的视觉骨架。

「小程序名称」从 v0.1.x 起只出现在顶栏、发现列表与文件名：它不参与归属判断、不做持久化、不能自动取得，缺省时还要显示「名称未识别」，并要求选中后多一次补填确认。它带来的辨识收益远低于流程与数据模型的复杂度。

外部参考项目 `wechat-channels-downloader`（Textual/Python）提供了另一套终端界面范式：品牌区 + 渐变分隔线 + 大留白 + 浅/深色跟随系统 + 可点击按钮 + 单一结果反馈。它证明终端里也能有清晰的品牌与层级，但它的单输入框/单结果流程与本项目「先定目标、再浏览大量候选、逐个下载」的流程不同，布局不能照搬。

## 决策

- **单主界面 + 统一目标选择区**：品牌区、主区、底栏常驻；AppID 输入与自动发现列表在同一区域并存，取消 `Ctrl+D` 手动/发现模式切换。用户确认目标后收起选择区，显示目标条、分类页签、候选表格与状态行；更换目标时展开同一区域，可取消，确认新目标才清空目标候选。
- **启动即发现**：打开程序后自动启动代理并持续发现，证书检查与系统授权沿用现有流程；发现结果只供用户选择，不自动确认目标、不覆盖输入或抢夺焦点，退出恢复原代理。`target.appID` 继续只作预填。
- **视觉以参考项目验收**：品牌区、绿系浅/深色板、间距、渐变线、外观下拉、按钮与底栏对齐 `wechat-channels-downloader` 的截图和控件风格；主内容区承载本项目目标选择与大量媒体候选。
- **复用现成 logo**：采用参考项目 PNG、ICO、ICNS，分别用于 TUI、Windows exe 与 macOS 应用图标，保留本项目名称和仓库链接。启动前探测 Sixel/kitty 与像素格，真图不可用时保留可用的降级显示。
- **快捷键与按钮对等**：下载、停止、详情、日志、清空、刷新、打开目录、更换目标、退出及各确认/错误恢复动作都有按钮和快捷键提示，并共用状态逻辑。分类键为 `1 全部 / 2 图片 / 3 视频 / 4 音频 / 5 直播 / 6 分段媒体`，默认全部；输入区按焦点处理文本编辑键。
- **删除小程序名称**：删除 `Target.Name`、`Candidate.AppName`、`target.name` 配置项与名称输入/展示/确认步骤，AppID 成为唯一目标标识；文件名改用日期与候选 ID 命名（见 [ADR 0012](0012-per-appid-download-layout.md)）。
- **保留嗅探与归属规则**：目标候选严格归属、来源未确认媒体按类型并入的机制不变（ADR 0008）。

## 备选方案

- **只换肤（改配色/字体/间距，保留三屏与密集表格）**：改动最小，但输入页、发现页、媒体页之间的跳转和「发现后再补填」的多余步骤仍在，观感目标无法达成。
- **迁移到 Textual/Python**：能最接近参考项目，但等于重做单二进制分发、Windows 证书/UAC、系统代理与 macOS 打包，风险与成本不可接受。
- **保留名称功能、仅重画界面**：名称不参与归属也不持久化，保留它只会继续占用确认步骤、配置项与文档篇幅；用户已明确要求删除。
- **发现与手动输入分为独立页面或模式**：需要来回切换，无法同时输入与观察发现结果；采用统一目标选择区，选定后收起以保留媒体列表空间。

## 后果

- TUI 渲染从字符串拼接改为有布局度量的组件化渲染；现有 `View()` 断言类测试与 README 截图需要重写/重拍。
- 主题、外观持久化（`downloads/ui.json`）、系统明暗检测、鼠标命中与响应式断点成为新的实现面。
- `target.name` 从配置模板与 schema 移除；旧 yaml 中的该键被忽略，不做迁移。
- logo 与应用图标接入分别涉及 TUI 输出、Windows 资源和 macOS 包配置；真图与降级显示均需验证。
- 悬停样式不得改变单行区域的高度和宽度；自动化需覆盖所有命中区域的进入/移出及按钮动作一致性，并补充真实终端缩放、滚动和覆盖层验收。
- 版本升至 0.2.0，并同步 README/知识文档/CHANGELOG。

## 实施记录（2026-10-25）

- 单主界面、统一目标选择区与启动即发现已按决策实现：启动时 `target.appID` 只预填输入框，运行时目标保持为空，确认后才 `SetTarget` 并收集目标候选；发现列表不自动选定、不覆盖输入、不抢焦点，选中身份按 AppID 保持。
- `Ctrl+D` 手动/发现模式切换与目标选择覆盖层已删除；AppID 输入与发现列表同时存在，媒体视图快捷键表不再出现 `Ctrl+D`。
- 外观下拉按“品牌区右侧单行控件 + 目标选择区 Tab 焦点”实现：`←/→` 直接切换、`Enter`/点击展开、`↑/↓` + `Enter` 或点击选择、`Esc` 关闭；媒体视图点击可打开；输入框聚焦时 `←/→` 只编辑文本。
- 媒体分类扩展为 `1 全部 / 2 图片 / 3 视频 / 4 音频 / 5 直播 / 6 分段媒体`，默认“全部”；直播独立页签且与视频互斥，m3u8 显示名改为“分段媒体”（目录调整见 ADR 0012、直播语义见 ADR 0013）。
- 操作按钮栏与页脚按钮、可点击覆盖层按钮、悬停尺寸稳定性与自动化回归均已实现：回归覆盖 12 种界面状态 × 110×40、80×24、60×20，断言物理行数、每行显示宽度与命中坐标稳定。
- 与需求的差异/后续项：ADR 0012 提到的 Windows 深路径长度防护本次未新增，列为后续项；真实微信、Windows Terminal 缩放/滚动与 macOS 真机验收仍待人工完成。
