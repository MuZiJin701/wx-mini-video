# 目标归属：严格 Referer 匹配 + 来源未确认媒体并入类型分类

状态：已确认（2026-10-25）。修订 [ADR 0003](0003-target-appid-filtering.md)。

后续分类修订：来源语义保持不变，v0.2.0 将直播独立、m3u8 分类显示名改为“分段媒体”，见 [ADR 0011](0011-single-main-surface-ui.md) 与 [ADR 0013](0013-live-stream-recording.md)。下文保留作出归属决策时的分类名称。

## 背景

v0.1.4 起，目标归属只接受恰好为 `https://servicewechat.com/<AppID>/<版本>/page-frame.html` 的 Referer。真实场景中，视频常由 H5/web-view 外壳（页面内 `wx.miniProgram`）或原生播放器/CKPlayer 直接请求，Referer 是 H5 页面或为空；实测某课程站点的视频请求甚至对 page-frame Referer 返回 403。因此严格门禁会在分类之前把视频整体丢弃，表现为“视频探测不到”。v0.1.7 发布截图已是 168 条 JSON 图片、0 视频。

## 决策

- **目标候选仍要求严格归属**：只有请求来源能解析出等于目标 AppID 的 page-frame Referer，才计入目标候选列表（`来源已确认`）。
- 媒体类响应（图片/直链视频/直链音频/m3u8）即使来源未知或属于其他 AppID，也作为**来源未确认**媒体（`?` 标记）按图片/视频/m3u8/音频并入对应分类；默认显示、可在配置关闭；下载时使用真实媒体响应的请求头（含 Referer/Cookie），以支持防盗链。
- **未知二进制兜底**：AppID 已匹配、状态 200/206、`Content-Type` 为 `application/octet-stream` 等未知类型且大小达到阈值（≥256 KB）时，作为“未知文件”候选收入目标列表，不自动缓存或下载。
- JSON 识别增强：支持相邻字段拼接（如 `url` + `urlToken`）与无后缀但字段名强相关的媒体地址。
- **H5 页面/脚本扫描**：对本机经过代理的 HTML/JS 响应（≤ 4 MB，正文含 `miniProgram`、`jweixin`、`ckplayer` 或 `<video` 标记）扫描内联的视频、m3u8 与音频地址，作为来源未确认候选按类型并入。候选 Referer 取页面自身；仅同源媒体复用页面 Cookie/Authorization，跨源只保留公开请求元数据；真实媒体请求发生后使用其实际鉴权头，后续页面扫描不覆盖该记录。因此**打开 H5 详情页即可出现候选，不依赖播放器真正发请求**。扫描结果标记为「H5 页面/脚本扫描（未播放验证）」，不作为来源已确认候选。
- 目标候选以目标代次检查在途响应；来源未确认媒体使用独立的清空代次，切换目标时保留，清空列表时使清空前在途响应失效。这样首屏扫描不会仅因确认目标而丢失，也不会在清空后重新入列。
- 发现阶段（尚未确认目标）不产生目标候选、不缓存播放列表，但来源未确认媒体（含 H5 页面扫描）照常收集；确认目标后按类型显示。这样打开小程序时自动加载的第一个页面不会因目标尚未确认而丢失。
- 二期可选：用诊断日志确认 web-view 文档请求的 Referer 后，再评估按文档 origin 自动归属；未验证前不实现，也不宣称无差别捕获。

## 备选方案

- **放宽 requestAppID 解析**（接受 query/port/origin 变体）：覆盖不了 H5 与无 Referer 请求，且服务器可能拒绝 page-frame Referer；不采用。
- **回退到 v0.1.3 的不过滤捕获**：能抓到视频，但其他小程序、视频号、公众号媒体混入，违背“列表清晰”的产品目标；不采用。
- **全量捕获 + 用户手动认领（参考 res-downloader）**：交互噪音大、无来源归属；仅吸收其“未知二进制兜底”和“按类型并入显示”经验。

## 后果

- 用户可以在对应类型分类中直接找到并下载 H5/web-view 视频；目标候选与来源未确认媒体混排，通过 `✓`/`?` 标记区分可信度，不再需要切换独立列表。
- 来源未确认媒体可能包含当前小程序之外的媒体，需限制容量并在文档中说明来源不可靠。
- H5 页面扫描会在打开页面时就产生候选，可能比用户实际播放的更多；下载失败可暴露过期或需登录的地址，用户需自行判断。
- 严格归属仍是默认路径；`来源已确认/来源未确认` 标记让用户能区分可信度。
