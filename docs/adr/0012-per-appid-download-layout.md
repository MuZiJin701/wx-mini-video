# 下载产物按目标 AppID 与资源类型分类

状态：已实施（2026-10-25）。修订 [ADR 0002](0002-portable-runtime-data.md) 中「下载目录平铺保存媒体」的布局描述。本日后续[需求修订](../tui-alignment-requirements.md)新增直播目录、将 m3u8 目录改为分段媒体；目录修订已按该需求实施，差异与后续项见文末“实施记录”。

## 背景

决策前所有媒体都平铺在 `<download.dir>` 根目录：图片、直链视频、直链音频、m3u8 合并产物、播放列表缓存与运行时文件混在同一层。旧文件名以 `AppName_候选ID前8位` 开头；名称删除后该前缀失效，且当用户先后下载多个小程序的资源时，根目录无法看出归属，只能靠当时尚无 AppID 字段的 `history.jsonl`。

参考项目按「每条内容一个文件夹」归档；本项目一次嗅探会产出大量候选，更合适的粒度是「每个小程序一个目录、每类资源一个子目录」。

## 决策

- **两级分类**：`downloads/<目标 AppID>/<资源类型>/`，类型目录为 `图片`、`视频`、`音频`、`直播`、`分段媒体`、`其他`。直播录制与普通视频分开，“全部”为汇总视图，不对应目录。
- **归属判定**：目标候选按其自身 AppID 归档；来源未确认候选（`?`）按「下载时的当前目标 AppID」归档。历史记录同时写入目标 AppID 与请求来源 AppID，供核对。
- **分段媒体集中**：合并后的 `.mp4`、播放列表缓存（`<候选ID>.m3u8`）、分片临时目录 `.segments/` 全部位于 `<目标目录>/分段媒体/`；分片清理语义不变。
- **按实际结果归档**：HTTP-FLV 直播录制进入 `直播/`，普通有限 FLV 文件进入 `视频/`；下载时才修正类型的候选也必须使用正确的最终目录。历史记录、完成提示及打开位置与实际文件一致，跨目录调整保留新流程中的重名和未保存录制保护。
- **运行时文件留根**：运行日志、debug 日志、`history.jsonl`、`ui.json`、根证书导出、受管 ffmpeg 与 `.ffmpeg/` 失败日志继续在 `downloads/` 根，不随目标切换迁移或删除。
- **文件命名**：`<类型前缀>_<YYYYMMDD-HHMMSS>_<候选ID前8位>.<扩展名>`，时间取本地时区下载开始时间；不再使用名称或 URL 原始文件名。
- **旧数据不做迁移兼容**：本次本地旧媒体、播放列表缓存、分片与未完成下载获用户明确授权，可一次性删除或覆盖；不要求跨目录续传或修复旧历史路径。配置、证书、外观与 ffmpeg 保留；后续新下载仍保护成品和未保存录制，程序正常启动不清空下载目录。该授权限于本次本地数据，不扩展为其他用户的自动清理行为。
- **AppID 目录名安全**：清洗非法字符、拒绝 `.`/`..`、处理 Windows 保留名、校验拼接后仍在下载根内；大小写敏感冲突时复用已有目录。
- **打开目录**：`o`/`Ctrl+O` 在目标已选且目录存在时打开 `<目标目录>`，否则打开下载根。
- `history.jsonl` 新增 `app_id`、`kind`、`attribution`、`source_app_id` 字段，保持追加写入与「仅成功记录」语义。

## 备选方案

- **只按类型平铺**（`downloads/图片/`…）：目录更浅，但多个小程序的资源仍混在一起，不满足按小程序分类的诉求。
- **按下载批次分目录**（`downloads/<AppID>-<时间戳>/`）：每次下载新建目录，会导致同一小程序反复产生碎片目录，浏览与去重都更差。
- **未确认候选放独立 `_unattributed/` 桶**：归属更真实，但用户选择并入当前目标目录，且历史记录可回溯来源；按此决定执行，并在文档中说明取舍。
- **自动迁移旧媒体与缓存**：需要推断归属、直播性质和旧路径关系；用户不要求保留本次本地旧下载数据，因此本轮不实现迁移机制。

## 后果

- 下载器与嗅探插件的路径计算需要统一：媒体输出目录、m3u8 缓存、分片目录、`history.jsonl` 字段、`o` 打开目录都要按新规则调整；受影响的测试断言与文档需同步更新。
- m3u8 分片路径在深目录下可能逼近 Windows 260 字符上限，实现时需缩短分片目录名并做路径长度防护。
- 切换目标后下载旧的未确认候选会落入新目标目录，这是已接受的取舍；详情与下载记录保留来源 AppID 供核对。
- 新布局与本次本地旧数据清理需明确区分；README/知识文档随实施更新，不能将本地清理授权泛化为升级时删除其他用户文件。

## 实施记录（2026-10-25）

- 两级分类已按决策实现：`downloads/<目标 AppID>/{图片,视频,音频,直播,分段媒体,其他}`；“全部”为汇总视图、无对应目录；原来的 `m3u8/` 目录被 `分段媒体/` 取代。
- HTTP-FLV 直播录制进入 `直播/`，普通有限视频（含确认是有限文件的 FLV）进入 `视频/`，m3u8 合并产物、播放列表缓存与 `.segments` 分片进入 `分段媒体/`，未知文件进入 `其他/`。
- 按实际结果归档已实现：`finalizeOutputPath` 在下载后按最终类型移动成品并修正默认类型前缀与 `.flv` 后缀；跨目录调整同时避开已有成品与同候选未保存录制，历史记录、进度与打开位置使用最终真实路径。归档目录创建或移动失败时保留成品在原目录并返回明确的归档失败错误（不按成功上报、不写历史），由用户处理后重试。
- AppID 目录名清洗、`.`/`..` 与路径穿越拒绝、Windows 保留名处理、`filepath.IsLocal` 校验均已实现；`history.jsonl` 增加 `app_id`/`kind`/`attribution`/`source_app_id`。
- 旧数据不迁移：旧版平铺文件与旧 `m3u8/` 目录不迁移、不自动删除、不复用，程序启动不清空 `downloads/`；本次本地旧下载数据的一次性清理是用户授权的人工操作，不写成程序行为。
- 实现差异/后续项：ADR 后果中提到的 Windows 深路径长度防护（缩短分片目录名、260 字符防护）本次**未新增**，作为后续项；当前分片目录仍为 `分段媒体/.segments/<候选ID>/<内容ID>/`。
