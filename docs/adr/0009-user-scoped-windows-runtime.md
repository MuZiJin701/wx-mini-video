# Windows 主程序以当前用户运行，仅证书操作提权

状态：已确认（2026-10-25）。修订 [ADR 0004](0004-windows-terminal-startup.md)。

## 背景

ADR 0004 让整个程序在启动时通过 UAC 提权，随后进入管理员 Terminal。该设计在“当前用户本身是管理员、UAC 只做同账号同意”的机器上工作正常：HKCU 不变，系统代理、用户证书与微信都处于同一用户上下文。

但真实场景中存在“标准用户运行微信 + 在 UAC 输入另一个管理员账号凭据”的机器。此时提权后的进程属于管理员账号：

- 系统代理写入管理员账号的 `HKCU`，运行微信的标准用户不会使用该代理；
- 证书虽然可以安装到本地计算机根信任库，但没有流量经过代理；
- 管理员账号的 HKCU 还可能没有 `ProxyEnable`，旧版读取逻辑会误判为致命错误。

用户确认该场景后，要求改为不整体提权的方案。

## 决策

- Windows 主程序始终以当前用户运行，`PrepareConsole` 只负责选择 Windows Terminal，不再请求 UAC；系统代理读取、启用、禁用与恢复都写当前用户 `HKCU`。
- 根证书仍安装到 Windows 本地计算机根信任库，以保持现有信任模型不扩大也不缩小；安装根证书、清理旧共享根证书时，按需通过 `ShellExecuteExW` 的 `runas` 启动**本程序的提权子进程**，使用 `SEE_MASK_NOCLOSEPROCESS` 取得并最终关闭进程句柄。
- 提权子进程通过 `--wx-mini-video-install-cert=<base64>` 或 `--wx-mini-video-remove-legacy-root` 参数识别，在 TUI 启动前由 `certificate.RunHelper` 处理后退出；证书内容通过 base64 参数传递，避免跨账号临时目录权限问题。
- 授权后父进程等待子进程结束（最长 2 分钟），读取退出码，并检查证书库确认安装/清理结果：证书出现或旧证书消失即成功，不使用退出码作为唯一依据。子进程失败退出或成功退出但证书状态不符时立即报错，不再轮询至超时；取消 UAC 单独提示。两分钟上限不包含等待用户处理 UAC 的时间。
- 子进程遇到操作错误时以系统弹窗显示具体原因，供用户查看；父进程保留退出码和最终状态错误。清理某个库时证书已不存在，只要复查确认旧证书均已移除，就不显示失败弹窗。
- 不改变证书私有材料的位置和 ACL：私钥仍保存在当前用户受限目录；管理员账号执行提权子进程时只读取传入的公开证书并写入机器信任库。
- macOS 维持既有行为：TUI 普通用户运行，设置代理/安装信任按系统授权提示处理。

## 备选方案

- **把根证书安装到当前用户根证书库（完全取消 UAC）**：实现最小、无提权，但需要先验证微信是否信任 `CurrentUser\Root`；未验证前不采用，避免把“能安装”误当成“微信已信任”。
- **保留整体提权并自动识别原始用户**：需要跨会话修改另一个用户的 HKCU，依赖用户 SID/凭据或加载注册表配置单元，复杂且容易产生新的恢复风险；不采用。
- **要求用户必须用运行微信的同一管理员账号启动**：会把标准用户挡在门外，不解决根因；不采用。

## 后果

- 标准用户 + 独立管理员账号的机器可以正常使用：代理作用于微信所在用户，UAC 只在首次安装证书或清理旧证书时出现。
- 同账号管理员用户仍可用；首次证书安装同样只需一次 UAC，之后启动不再提权。
- 提权子进程无需可见控制台，具体失败原因通过系统弹窗呈现，父进程通过进程句柄及时获知结束；实际超时会明确提示子进程可能仍在运行。
- 自动化测试覆盖启动编排（仅 Terminal 安全重启）、证书提权参数解析、旧证书清理派发、真实普通子进程的成功/失败/超时、取消 UAC 的模拟路径及最终证书状态校验；真实 UAC、错误弹窗、标准用户与微信流量仍需在对应机器上人工验收。
- Windows 文档与 `AGENTS.md` 不再写“启动时请求管理员权限”，改为“仅证书安装/清理时请求”。
