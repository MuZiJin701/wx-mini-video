# TUI 对齐、目标选择与媒体分类需求

状态：代码已实施、自动化回归已通过（2026-10-25），实机验收待完成。用户已整体确认本文需求；当前实现、支持边界与后续项见文末“实施注记”。

## 用户诉求

- TUI 显示界面与本地参考项目 `D:\data\projects\wechat-channels-downloader` 一致，既可使用快捷键，也有对应按钮可点击。
- 修复鼠标移动到某些位置时界面错乱的问题，用户已提供截图。
- 保留 AppID 手动输入，并与自动发现同时呈现。
- 复用参考项目的 logo，同时用于程序图标与 TUI 品牌区。
- 将直播流作为与图片、视频等同级的标签，m3u8 分类改名为分段媒体，下载目录同步调整；本轮直播录制范围保持 HTTP-FLV。

## 澄清时的基线与问题（实施前）

- 参考项目使用 Textual/Python；本项目使用 Bubble Tea/Lip Gloss。参考界面为品牌区、外观下拉、渐变线、主内容区、操作按钮与底栏。本项目仍需承载目标选择、媒体分类、大量候选及直播录制。
- 参考项目有 `downloader/assets/logo.png`、`logo.ico`、`logo.icns`。实施前本项目嵌入的是另一张 PNG，Windows exe 与 macOS 应用图标尚未接入；当前三种资产均已复用并接入构建。
- 实施前通过临时 Go overlay 复现悬停错乱，不依赖真实终端图片绘制：110×40 界面悬停未选中候选行后，输出从 40 行增至 68 行；部分页签、目标切换与发现列表项悬停后增至 42 行。根因是单行区域复用了带边框与内边距的 `buttonHover` 样式；当时的测试未覆盖渲染尺寸。当前已分离样式并补充尺寸与命中回归。
- 复现时本地 `dist/wx-mini-video.exe` 构建版本为 `4d47e22`，与当时源码一致；该记录用于追溯问题，不表示当前构建版本。
- “小程序发现”指观察经过代理的网络活动并登记请求来源 AppID，不是枚举所有已安装小程序，也不等于自动选定目标。目标选择及严格归属是不同步骤，见 [ADR 0008](adr/0008-target-attribution.md)。

## 已确认方向

1. **视觉对齐**：以参考项目的品牌区、配色、间距、外观下拉、按钮与底栏为验收基准；主内容区保留本项目所需的目标选择、分类与媒体表格。下载、停止录制、详情、日志、清空、刷新、打开目录等业务动作均有对应的可点击按钮与快捷键提示，见修订后的 [ADR 0011](adr/0011-single-main-surface-ui.md)。
2. **统一目标选择区**：保留 AppID 手动输入，并与小程序发现列表同时展示、并行工作；用户可以一边输入 AppID，一边看到持续更新的发现结果。不再通过 `Ctrl+D` 切换手动输入与发现模式，也不将手动输入隐藏为次级备用入口。
3. **用户确认目标**：发现不等于选定。无论发现一个还是多个小程序，仍由用户点击或按 Enter 确认目标，不自动代选；新发现的网络活动不得自行切换已选目标。
4. **启动即发现**：程序打开后自动启动代理并持续进行小程序发现，界面显示启动状态。首次需要证书检查或系统授权时沿用现有流程；正常退出恢复原代理。
5. **收起与展开**：用户选定目标后收起完整输入框与发现列表，保留当前目标条和更换目标按钮，为媒体表格留出空间；更换目标时展开同一个目标选择区。后台发现持续进行，下载或录制中禁止切换目标。

## 媒体分类

### 分类基线与协议边界

- 实施前页签为全部、图片、视频、m3u8、音频，直播混在视频中。当前已按下文采用六个分类，直播与普通视频互斥；传输处理仍复用 FLV 路径。
- m3u8 是播放列表格式，既可承载视频，也可承载音频，且可用于直播与点播。[RFC 8216](https://www.rfc-editor.org/rfc/rfc8216.html#section-8.4) 给出纯音频播放列表；`EXT-X-ENDLIST` 表示不会再追加分片，参见[第 4.3.3.4 节](https://www.rfc-editor.org/rfc/rfc8216.html#section-4.3.3.4)。仅凭 `.m3u8` 后缀不能确定内容类型或是否直播。
- 本项目当前没有按播放列表、轨道信息可靠区分 HLS 视频、音频与直播的逻辑。现有 m3u8 下载可能只保存当前捕获列表的快照；[ADR 0013](adr/0013-live-stream-recording.md) 明确尚不支持 HLS 持续直播录制。调整标签不能把这种行为表述为已具备直播录制能力。
- 页面筛选、下载处理与文件归档是不同决定。当前直播录制与普通视频分目录，m3u8 产物与缓存统一进入“分段媒体”；完整布局见下文。

### 已确认的分类方向

1. **直播独立且互斥**：直播候选进入“直播”和“全部”，不再混入普通“视频”；疑似直播保留明确标记，确认是有限 FLV 文件后归回视频。直播状态被修正时按候选身份维持合理选择，不误操作另一条资源。
2. **分段媒体分组**：保留独立分类，m3u8 标签改称“分段媒体”，详情保留 m3u8/HLS 格式信息。HLS 视频、音频与直播播放列表均保留在该分组，不因页面改名丢失入口或改变现有下载路由。
3. **直播录制范围**：本轮保持已支持的 HTTP-FLV 持续录制，HLS（m3u8）持续直播录制留作后续需求；分段媒体界面不宣称已支持持续直播录制。
4. **顺序、数字键与默认页签**：采用 `1 全部 / 2 图片 / 3 视频 / 4 音频 / 5 直播 / 6 分段媒体`；进入媒体视图默认“全部”。未知文件仍在“全部”中可见，不额外新增分类。

### 已确认的新目录

- 下载目录随界面分类变化，新下载布局为：

  ```text
  downloads/<目标 AppID>/
  ├── 图片/
  ├── 视频/
  ├── 音频/
  ├── 直播/
  ├── 分段媒体/
  └── 其他/
  ```

- HTTP-FLV 直播录制进入 `直播/`；普通有限视频（含确认是有限文件的 FLV）进入 `视频/`；分段媒体的合并产物、播放列表缓存及 `.segments` 统一进入 `分段媒体/`。页面“全部”是汇总视图，不新增对应目录。
- 实际响应修正候选类型后，最终文件也要归入正确目录，包括下载时才确认的直播；历史记录、完成提示及打开文件位置必须使用真实最终路径。本次旧数据清理之外，新流程中的跨目录调整不得覆盖已有成品或未保存录制。
- 运行日志、debug 日志、`history.jsonl`、`ui.json`、证书导出与受管 ffmpeg 等继续留在下载根目录。

### 已确认的旧数据处理

- 用户明确表示本次旧下载数据不重要，可以直接删除或覆盖；不要求迁移旧文件、恢复旧缓存或跨目录续传旧 `.part`。
- 本次实施可一次性清理当前项目下载目录中的旧媒体、播放列表缓存、分片和未完成下载，并按新布局重新开始。旧下载历史不提供路径迁移或修复保证。
- 清理范围限定为本次本地旧下载数据；配置、证书、外观偏好、受管/随包 ffmpeg 等运行时资料保留。程序正常启动与后续下载继续遵守文件保护规则，不引入每次启动清空下载目录的行为。
- 允许处置旧数据不改变新下载的重名保护、未保存直播录制保护、停止/断流保存及保存失败保留现场要求。

## 交互与验收要求

以下要求已随完整需求整体确认。

### 启动、发现与目标选择

- 初始主内容区同时显示 AppID 输入、确认按钮、发现状态与已发现列表。未发现时提示用户在 PC 微信打开小程序，同时允许输入 AppID；持续等待，不因超时自动选择或退出。
- 输入、发现列表与按钮具有明确的焦点与选中态。输入框内 Enter 只确认输入值（空值报错），发现列表内 Enter 只确认选中项。确认按钮优先使用主动选择的发现项，继续编辑输入后恢复输入值优先；没有主动选择且输入为空时才使用列表当前项。鼠标点击确认/取消不受旧键盘焦点影响；发现更新不得覆盖输入、抢夺焦点或使选中的 AppID 随重排变化。
- 输入框内的字母、数字及左右方向键按文本编辑处理；业务单键不得吞掉 AppID 输入。`Ctrl+D` 不再承担模式切换；输入区与发现列表在同一区域并存。
- `target.appID` 沿用预填含义；启动自动发现不表示自动确认预填目标。用户确认前仍遵守 ADR 0008 的发现阶段归属规则。
- 更换目标区允许取消，取消保留当前目标、候选与已输入内容；确认新目标才按现有规则切换。启动失败提供可点击的重试与退出入口。

### 按钮与快捷键

- 每个业务按钮标注对应快捷键，点击和快捷键走相同动作；禁用状态与失败处理一致。列表选择、滚轮与分类页签继续支持鼠标。
- 媒体操作提供下载、停止下载/录制、详情、日志、清空、刷新、打开目录、更换目标与退出按钮；详情/日志及目标选择区提供关闭或取消入口。确认、证书与代理恢复失败界面也提供对应按钮。
- 延续 `d/Enter` 下载、`x` 停止、`i` 详情、`l` 日志、`c` 清空、`r/Ctrl+R` 刷新或重试、`o/Ctrl+O` 打开目录、`s` 更换目标、`q/Ctrl+Q` 退出；数字分类键按已确认的 `1`–`6` 顺序映射。输入焦点和覆盖层按其上下文处理这些键；输入框内单键是文本，重试用 Ctrl+R，退出用 Ctrl+Q/Ctrl+C 或按钮。
- 目标选择区使用 Tab/Shift+Tab 切换输入、发现列表与按钮焦点，列表用上下方向键导航；媒体视图的 Tab/Shift+Tab 分类习惯保留。外观下拉有独立焦点，避免占用输入框的左右方向键。
- 录制与下载中禁用再次下载和更换目标，停止按钮可用；退出仍先确认并等待收尾，保存失败保留错误界面。空列表时下载、详情等无对象动作不可用。

### 视觉、图标与兼容性

- 沿用 Go 单二进制、Windows 与 macOS 支持。对照参考项目截图验收品牌区、配色、外观下拉、按钮、渐变线与底栏，媒体主区按本项目候选列表承载量布局。
- 复用参考项目现有 PNG、ICO、ICNS，分别用于 TUI、Windows exe 和 macOS 应用图标；名称与仓库链接沿用本项目。真图不可用时保持可用的降级显示。
- 自动化覆盖所有悬停区域进入与移出，断言物理行数、每行显示宽度及命中坐标稳定；覆盖目标选择、媒体列表、外观、详情、日志、确认与错误状态。
- 实机验收至少覆盖 110×40、80×24、60×20，浅色/深色/跟随系统、缩放、滚动、覆盖层开关、真图与降级。小窗口允许缩减次要信息并滚动操作区，主要操作仍可达。
- 验收包含快捷键与按钮动作一致、空列表、多个发现结果持续更新、录制停止、保存失败取消退出及系统代理恢复；更新受影响 README、维护指南与操作截图，执行项目要求的测试及打包验证。
